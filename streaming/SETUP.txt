SPECIFIC WINDOW CAPTURE
For Coding and Demo, add Window Capture for a dedicated public window. Put the
capture BELOW Graphics in Sources. Fit into x=48, y=136, width=1824, height=840.
Keep the original aspect ratio; letterbox rather than stretching text.
Add a black Color Source below the capture if letterboxing leaves blank space.
Use the strictest window-title matching option available; disable cursor capture
unless needed. Verify behavior if the target window closes or is renamed.
Keep OBS on monitor 2 and the public coding/demo window on monitor 1.
Use a separate browser profile with no saved accounts for public demos.
Selected-window capture can still reveal secrets INSIDE that window. Use safe
example data; close .env files, password managers, private tabs and messages.
Keep phone mirroring/location windows closed. Do not capture a full display.
Do not add a Discord visual capture or chat widget without a deliberate public
channel and permission to show the conversation.

SEPARATE AUDIO CONTROLS
In Settings > Audio, explicitly disable global Desktop Audio and global Mic/Aux
devices. This prevents default device capture and duplicate audio on first use.
Create an Audio scene with three separately named sources:
  MIC: Audio Input Capture, select SteelSeries Sonar - Microphone explicitly.
  GUESTS: Application Audio Capture, select Discord; audio only, no visual source.
  MUSIC: VLC Video Source playlist if OBS offers it; loop the local licensed files.
If VLC source is unavailable, use Media Source with a single licensed local
file and Loop enabled. A playlist requires VLC support; do not install it yet.
Reference the same Audio scene in each production scene to share mixer controls.
Keep all three sources muted initially. Set all audio monitoring to Monitor Off
unless a specific headphone monitoring route is intentionally configured.
Wear headphones. Ask guests to join a dedicated voice channel with agreed audio
broadcasting. Discord application audio can include notifications and other
Discord calls; suppress notifications and verify the selected session.
Do not route both Sonar Chat and Discord application capture to the stream.

RECORDING AUDIO TRACKS
Track 1: audience mix (mic + guests + licensed music), selected for streaming.
Track 2: microphone only. Track 3: Discord guests only. Track 4: music only.
Enable tracks 1-4 for local MKV recordings in advanced output settings.
YouTube VODs use the transmitted audience mix; local isolated tracks do not
remove music or conversations from a YouTube replay.
Mic target while speaking: approximately -18 to -9 dBFS, with peaks below -6.
Bring guests to a comparable level; keep background music quieter than speech.
Use a limiter only after confirming normal microphone gain. Start music around
-30 to -24 dBFS and adjust by listening to a local recording.
