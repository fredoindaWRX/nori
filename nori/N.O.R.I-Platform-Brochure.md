# N.O.R.I.
## One intelligence. Every device. No lost context.

N.O.R.I. is a connected intelligence and operating-system platform designed to move one continuous conversation and one accountable stream of work across personal computers, servers, edge nodes, vehicles, scanners, robots, and home devices.

## The platform core

### Genesis
N.O.R.I.'s model runtime and model registry. Genesis selects a compatible local or remote model, applies the machine's resource policy, and exposes one stable N.O.R.I. inference boundary.

### Nexus
Secure continuity between trusted N.O.R.I. devices. One-time pairing, certificate identity, household or organization boundaries, revocation, and permissions determine which nodes may communicate.

### Matrix
N.O.R.I.'s creation and build environment. Matrix coordinates code, games, documents, media, simulations, tests, packaging, and recovery as visible work with reviewable outputs.

### Seth
The N.O.R.I.-owned model host and router. Seth manages model health, loading, routing, capacity, and failure recovery without making Ollama a required dependency.

## Twelve Knights

The Knights are specialized workers with one shared purpose. Planned roles cover Research, Code, Planner, Vision, Voice, Data, Devices, Robotics, Security, Reviewer, Verifier, and Recovery. Each worker receives only the tools and permissions required for its assignment. Architect is the currently implemented proposal worker; other Knights remain staged roadmap roles until their execution contracts and verification are complete.

## Three operating systems

### N.O.R.I. Home OS
A polished daily computer environment designed for browsers, media, files, Windows-compatible application paths, Steam gaming, Discord, creation tools, smart-home control, and natural conversation with N.O.R.I.

### N.O.R.I. Server OS
An always-on foundation for models, workers, storage, networking, monitoring, backups, updates, and recovery. Home and Server are designed to pair through Nexus so a personal device can send approved work to the stronger server node and receive the result in the same session.

### N.O.R.I. Robotics OS
An edge platform for robots, vehicles, diagnostic scanners, sensors, actuators, and simulation. The hardware abstraction layer exposes consistent capabilities while deterministic controllers, limits, emergency stops, and audit trails remain authoritative for physical motion.

## N.O.R.I. Drive

N.O.R.I. Drive carries the owner's approved identity and conversation into supported vehicles. Depending on the vehicle, it can appear through a driver-optimized phone projection, a native Android Automotive application, a manufacturer-approved interface, or an enrolled diagnostic adapter using OBD-II, supported CAN diagnostics, J2534 pass-through hardware, or a compatible scanner such as Foxwell.

The parked setup is simple: **Pair. Verify. Profile. Ready.** N.O.R.I. discovers the real capabilities of that vehicle and adapter, shows the owner what is available, and issues a revocable identity. Diagnostics remain the default. Clearing codes, relearns, actuator tests, coding, module programming, and other service actions require explicit support, owner approval, stable power, short-lived authority, and a complete audit history.

## Research in view

N.O.R.I.'s workspace is designed around three coordinated views:

- **Sources** shows the files, references, devices, and evidence being used.
- **Research** shows live synthesis, progress, and the knowledge relationships being formed.
- **Work** shows commands, edits, verification, and completed outputs.

The particle avatar looks and moves between these views so the visual state reflects where N.O.R.I. is focusing. Idle and conversation use a close three-dimensional face. Thinking pulls back to the full particle body while electric-blue neural paths fire through selected regions.

## Adaptive hardware and the N.O.R.I. node

The installer profiles CPU, memory, GPU, storage, and networking, then proposes model sizes and worker limits that the machine can run responsibly. Customers may use compatible hardware or a qualified N.O.R.I. node. A compact always-on Edge Node can discover approved home devices and coordinate light services; larger Server Nodes can host models and the Knights.

## Learning across a trusted fleet

Within one owner's paired fleet, capable nodes can advertise health and available resources so work is routed to the right machine. Optional diagnostic reporting can help improve future releases, but it must be explicit, inspectable, sanitized, deletable before upload, and separate from private conversations, files, camera, microphone, and raw vehicle data by default. Updates must be signed, hardware-matched, versioned, and reversible.

## Voice, vision, and presence

N.O.R.I. is designed for low-latency wake-word continuation, natural speech, owner voice enrollment, expressive lip and face motion, head turns, and a volumetric particle identity. The visual system uses a near-black Ghost Purple base with a deep purple sheen and selective Ghost Blue neural activity.

## Trust and control

N.O.R.I. shows what it plans to do, what authority it has, which worker is active, and what changed. Permissions, approval gates, spending limits, simulation modes, signed updates, rollback, and dated audit logs keep powerful automation understandable and accountable.

## Installation

N.O.R.I. Home OS and Server OS are being developed for USB installation on compatible x86-64 PCs through a branded graphical setup for language, keyboard, network, hardware assessment, edition selection, disk selection, account setup, installation, and first boot. Robotics OS uses simulator and board-specific deployment profiles. Current release status and verified limitations are maintained separately from this product vision.

## The promise

Plan. Execute. Verify. Recover. One persistent intelligence that can research, create, operate, and help across the digital and physical world while remaining yours.
